0. 目标与范围
目标

把前端模板变成可运行的产品闭环：

签到(行为入口) → 获得抽奖次数 → 幸运转盘(刺激) → 奖励入账(多为冻结) → VIP(放大器) → 满足条件发起提现(风控点)
并叠加：推广会员等级 V1~V5 + 直推/间推收益 + 达标奖励金。

MVP 范围（第一阶段必须完成）

登录/注册/邀请码体系

签到与连续奖励+断签惩罚

抽奖次数与幸运转盘（概率、奖池、日志、幂等）

钱包账本（余额/冻结/积分）

VIP（权益：额外抽奖、提现加速/门槛）

提现（申请→审核/排队→完成/拒绝）

推广关系链 + V1~V5 达标统计 + 奖励发放

风控：设备/IP/频率/重复账号/提现审核策略

1. 技术栈建议（适合 Replit）
推荐方案：Node.js + Express + PostgreSQL（或 Supabase）

后端：Node.js(Express/NestJS 二选一；MVP 用 Express 更快)

数据库：PostgreSQL

Replit 可用 Neon（外部 PG）或 Supabase（外部 PG + Auth 可选）

缓存/队列（可选）：Upstash Redis（用于频控、锁、幂等）

定时任务：node-cron（MVP）→ 后续可换 BullMQ/Cloud scheduler

鉴权：JWT（MVP），后续可接 Supabase Auth

如果你前端模板已经有 Supabase 相关结构，也可以直接走 Supabase（更省登录/表结构/权限成本）。但你说“只有前端模版”，我默认你还没后端。

2. 项目结构（Replit 目录建议）
/app
  /frontend        # 你现有的前端模板（Vite/Next 任选）
  /backend
    /src
      app.js
      routes/
      controllers/
      services/
      middlewares/
      jobs/
      utils/
    package.json
  /shared           # 前后端共享 types/常量（可选）
replit.nix / .replit


启动方式：

backend：npm run dev 监听 3001

frontend：npm run dev 监听 5173（或 3000）

Replit 用一个 npm run start 同时拉起（concurrently）
